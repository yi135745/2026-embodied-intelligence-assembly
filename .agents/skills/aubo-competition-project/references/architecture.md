# 工程架构与职责边界

## 设计目标

本项目追求的不是抽象程度最高的框架，而是在比赛现场以少量稳定入口完成“语音—拍照—理解—定位—抓放”，并能从图片、JSON 和日志追溯失败发生在哪一层。结构优化必须降低现场认知负担，不能牺牲单一真源、可回退和可诊断性。

## 依赖方向

```text
main.py
  └─ task/task1.py, task/task2.py       流程编排
       ├─ modules/*                     彼此平行的功能能力
       │    ├─ contracts/*              纯数据与数值契约
       │    └─ drivers/*                SDK / HTTP 边界
       └─ runtime/*                     唯一正式现场数据加载

tools/* ──> modules/*                   标定、调试、诊断
test/*  ──> task/* + modules/*          离线契约验证
```

保持依赖单向：功能库之间不得横向导入，也不导入 `task/`、`tools/` 或 `runtime/`；业务任务不复制 SDK 调用。只有任务和工具可以组合多个功能库。

## 顶层职责

| 路径 | 责任 | 不应承担 |
| --- | --- | --- |
| `main.py` | 初始化服务、两段式语音派发、完成状态、最终断开机器人 | 视觉算法、任务卡规则、抓放几何 |
| `task/task1.py` | 任务一到位、拍照、模型理解、播报的编排 | MVS/Qwen/AUBO 的底层实现 |
| `task/task2.py` | 三次拍照、整份计划预检、逐步执行、成功后提交状态和日志 | HSV细节、JSON规则、标定拟合、SDK调用 |
| `modules/voice.py` | `local` 与 AI 盒子语音适配，统一听/说/唤醒接口 | 任务派发与业务状态 |
| `modules/camera.py` | 单帧采集及调试图入口 | 颜色识别与任务规划 |
| `modules/interpreter.py` | 图片上传、任务一文字、任务二合法 JSON 解析 | 任务协议校验、坐标、角度、高度和运动决策 |
| `modules/robot.py` | AUBO 连接、单位转换、安全运动、抓放、Tool IO | 颜色和任务语义 |
| `contracts/task2.py` | 视觉目标、规范角、持久补偿结构 | 文件、设备或流程 |
| `modules/task2_perception/` | 颜色/形状检测、公共矩阵换算、两区偏移合成、方向换算 | 标定拟合、规划和执行状态 |
| `modules/task2_planning.py` | 动作协议、标称终态、叠放高度、方向和命令补偿 | 视觉、网络或机械臂访问 |
| `modules/task2_calibration/` | 拟合、质量、版本、闭环及XML数学 | 运行时感知、现场交互和设备生命周期 |
| `drivers/` | AUBO、MVS、DashScope、AI盒子底层适配 | 任务规则和跨设备编排 |
| `runtime/site_data.py`、`runtime/task2_state.py` | 加载唯一正式拍照位、偏移、绑定和补偿状态 | 视觉、规划或设备动作 |
| `tools/setup/` | 点位与通用硬件设置 | 正式任务入口 |
| `tools/task2/workflow/` | 当前推荐的调参、公共矩阵、闭环偏移、审计、恢复 | 临时试验脚本堆积 |
| `tools/task2/diagnostics/` | 只读或受控诊断 | 自动成为正式数据源 |

## 数据层次

| 层 | 路径 | 语义 |
| --- | --- | --- |
| 静态配置 | `config.py` | 硬件地址、阈值、开关、Z、高度、文件路径和默认 HSV；不是四点位姿或XY偏移的第二副本 |
| 现场正式状态 | `data/` | 唯一位姿 JSON、当前 XY 偏移、本机调参；修改会改变实机行为 |
| 正式资源 | `resources/` | 公共标定 XML、模板、质量绑定、完整报告、历史备份、SDK资料 |
| 运行证据 | `output/` | 原图、mask、标注、候选、日志和调试报告；允许清理，不得作为唯一运行依赖 |
| 离线验证 | `test/` | Fake 设备、纯数学、文件契约和回归；不连接真实硬件 |

不要让一个值在多个层都可编辑。例如位姿从 `data/aubo_poses.json` 加载后覆盖运行时 config；这是读取接口，不代表 config 也拥有一套正式位姿。

## 正式入口和实验入口

- `python main.py` 是集成入口。
- `task/task1.py`、`task/task2.py` 是绕过语音派发的任务入口，仍可能连接硬件。
- `tools/README.md` 中的 workflow 是现场正式调试链路。
- diagnostics 默认不等于“绝对安全”：阅读脚本是否移动、拍照、写文件。
- 已删除的旧工具只通过 Git 历史回看，不保留平行运行入口。

## 结构变更判断

以下属于架构变化，不能当作局部修复直接实施：

- 新增另一份正式矩阵、位姿、偏移、HSV 或任务状态文件；
- 让 `task/` 直接使用 SDK/HTTP，或让 `modules/` 反向依赖任务；
- 改为装配中重拍、视觉闭环、并发执行或自动恢复；
- 改变“一次计划预检、成功后提交”的事务边界；
- 把候选、日志或 `output/` 变成正式运行前提；
- 用更宽松的门禁替代现场问题定位。

遇到这些需求，先向用户呈现现状、理由、数据迁移和回退方案，再等待明确选择。
