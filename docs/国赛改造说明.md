## 数据与调用边界

模型返回每次抓放的语义，角度和坐标由视觉/程序计算：

```json
[
  {"step": 1, "source_color": "红色", "target_type": "tray", "target_color": "黄色"}
]
```

上例只展示单项结构，不是完整任务卡。前六项必须是红橙黄绿蓝紫各一次，六色托盘各一次。后续项必须是青/粉/棕来源、`block`目标，目标必须已在前面的动作中放置且顶面未占用。禁止重复来源、缺失字段、非连续编号、自动补齐或重排。最后一句含多次抓放时按卡面展开。

任务书最后阶段动作数尚待样例确认，`TASK2_EXPECTED_STACK_COUNT=None`暂接受1~3次叠放；可设1/2/3精确校验，0仅供六步省赛回归。这个配置不能证明OCR没有漏掉最后一句中的动作，拿到明确样卡后应收紧。

| 文件 | 当前职责 |
| --- | --- |
| `modules/interpreter.py` | 按新提示词识别卡面，保存带时间戳的原文与解析动作 |
| `modules/task2_planning.py` | 动作校验、几何校验、方块终态推演、完整抓放位姿生成 |
| `modules/task2_perception/` | 九色方块/六色托盘、轮廓中心、图像角、基座角、标定转换 |
| `task/task2.py` | 三次拍照、复述、预检完整计划、逐步执行和提交状态 |
| `modules/robot.py` | 只接收抓/放位姿，执行抬升、旋转、平移、吸取和释放 |
| `main.py` | 仅把成功任务计入完成状态，两项成功后最终播报 |

任务卡、方块区、托盘区各拍一次。后续不重拍。`placed_block_map`仅在抓放返回成功后提交；计划里的`placed_state`是预测终态，不能当作执行成功记录。任何步骤失败后停止剩余计划，写入失败状态和日志。

这依赖拍照后场景不再移动、吸取时不打滑、实际落点接近指令落点。若裁判在装配途中移动物块/托盘，需要另行增加重拍重定位逻辑；当前没有该功能。

## 方向对准

保留原始`angle_deg`，增加`robot_angle_deg`。从 `cv2.minAreaRect` 的一条边取两端点，通过现有九点矩阵变换，再用`atan2(dy, dx)`求机器人XY方向角。与直接相减图像角度相比，这会考虑图像Y轴方向及标定矩阵的旋转/缩放；不再配置未经验证的正负号。

正方形每90度等价：`delta = (target_angle - source_angle + 45) % 90 - 45`。
AUBO仓库SDK说明TCP姿态为ZYX欧拉角（rad），在现有竖直吸取方式下保持抓取rx/ry，放置 `rz = pick_rz + radians(delta)`，归一化到[-pi,pi)。到位判断也处理±pi等价。

托盘目标使用本次识别角度；方块目标使用它上次放置后的预测方向。`TASK2_ROTATION_ENABLED=False`时不对准，并记录原来的实际方向，避免给后续叠放虚构目标角度。

`TASK2_ROTATE_AT_CLEARANCE=True`时，吸起并抬升后在抓取点上方旋转，再移动到目标上方。共同净空高度取当前Z、安全Z、抓取Z+抬升量、放置Z+抬升量的最大值。关闭该开关时允许在高位平移过程中旋转。

仍需现场确认：矩阵坐标与机器人基座对应、TCP位于吸盘中心、物块吸取后不相对吸盘滑动、拍照高度/姿态与标定匹配。单目平面标定对不同物块高度的投影误差留到精度调试阶段处理。

## 高度计算

全部物块共用唯一实测高度 `TASK2_BLOCK_HEIGHT_MM`，它同时用于方块拍照 Z 增量与叠放层高。`TASK2_BLOCK_PICK_Z` 和 `TASK2_TRAY_PLACE_Z` 是在该统一高度下实测的 TCP 值；抓取下压量不得伪装成按颜色物块高度差。

```text
抓取TCP Z = TASK2_BLOCK_PICK_Z
落盘TCP Z = TASK2_TRAY_PLACE_Z
叠放TCP Z = 目标方块已记录的顶面TCP接触Z + TASK2_BLOCK_HEIGHT_MM
```

例如统一物块高度30、放置Z=183，首块顶面TCP接触Z为183；再叠一块为213，继续叠一块为243。`top_tcp_z`指同一吸盘接触方块顶面时的等效TCP Z，包含工具偏置；它不是裸物理表面坐标。

任务书明确高度未知，必须现场测量唯一的 `TASK2_BLOCK_HEIGHT_MM`。上述公式假定工具 TCP、接触压缩量和来源物块起始支撑面一致；若需要额外下压，应重新标定抓取 Z，而不是伪造物块高度。

## 颜色及调参兼容

保留省赛六色阈值，增加青/粉/棕初值。颜色覆盖率、色相和Lab继续联合评分，但由SciPy匈牙利算法代替全排列。拒绝代价高于 `TASK2_COLOR_MAX_ASSIGNMENT_COST` 的匹配，也拒绝多个颜色指向同一中心；这不是识别准确率保证，新增三色仍需实拍调试。

旧六色调参JSON按颜色合并，新增三色不会被覆盖掉。调参工具方块支持1~9、托盘1~6，保存一个分区时保留另一区域数据。正式流程不读取`task2_verified_trays.json`。

## 离线验证和联调

```powershell
python -m unittest discover -s test -p "test*.py" -v
```

测试包括指令拒绝规则、九色合成图、基座方向变换、90度/±pi边界、三层高度、末端高位旋转、失败不提交状态、三次拍照九次抓放的模拟流程及完成播报。使用Python3.10环境；不加载语音模型、不接硬件、不调外部API。九点测试读取XML自身的9对对应点，避免旧测试硬编码失效的像素原点。

当前实物联调次序：

1. 先设置 `TASK2_EXECUTE_ROBOT=False`，用三张调试图验证完整计划。该模式跳过所有拍照位移动和抓放；仍需有效的位姿/XY标定文件以计算坐标，LLM环节仍会调用API，除非测试中使用FakeLLM。
2. 拿到9个实物后调青/粉/棕阈值，测高度，复核参考抓放Z。
3. 先单块对准托盘，再单块叠放，核对角度方向、吸盘中心和放置精度。
4. 用独立语音测试脚本验收盒子录音、播报和“小具同学”文字唤醒，再执行完整任务，测总时长和成功率。

语音 HTTP 接口已接入，但原生“小具同学”关键词模型、播报中唤醒打断、备用文本输入、任务一场景解析增强、五分钟计时、装配途中重定位尚未完成。
