# 具身智能精密装配赛 · 项目流程说明

> 面向团队内部的项目总结。本文档与代码一一对应，比赛现场若发现内容与代码不一致，以代码为准。

## 1. 项目概述

本方案通过「语音唤醒 → 语音识别派发任务 → 工业相机拍照 → 视觉识别 → 机械臂抓放」的闭环，完成两道赛题任务：

| 任务 | 目标 | 涉及能力 |
|------|------|----------|
| 任务一 | 识别任务卡一的场景内容并语音播报 | 机械臂到位 + MVS 拍照 + Qwen 视觉大模型 + TTS 播报 |
| 任务二 | 阅读任务卡二装配指令，按序把六色方块抓放到对应颜色托盘 | 任务卡解析 + OpenCV 六色定位 + 视觉标定 + AUBO 抓放 + 吸盘控制 |

## 2. 系统架构（分离式）

底层能力被封装为独立模块，业务流程只做编排，不直接碰底层库。

```
.
├── main.py                     # 集成入口：语音唤醒 + 派发任务一/二
├── config.py                   # 全部现场可调参数（集中配置）
├── task/
│   ├── task1.py                # 任务一流程（可直接运行，独立测试入口）
│   └── task2.py                # 任务二流程（可直接运行，独立测试入口）
├── modules/                    # 底层能力封装库
│   ├── voice.py                # FunASR 语音识别 + pyttsx3 语音播报（VAD 录音、热词纠错）
│   ├── vision.py               # 海康 MVS 工业相机拍照封装
│   ├── robot.py                # AUBO 机械臂 SDK 封装（运动 + 末端吸盘 IO）
│   ├── llm.py                  # DashScope Qwen 视觉大模型封装
│   └── task2_vision.py         # 任务二 OpenCV 视觉 + 坐标标定（六色检测、九点标定）
├── task2_tuner.py              # 任务二 HSV/曝光/增益 交互式调参工具
├── task2_offset_calibrate.py   # 方块/托盘 XY 偏移 + 抓放 Z 标定工具
├── task2_tray_verify.py        # 托盘坐标人工验收工具
├── task2_vision_test.py        # 任务二视觉离线测试
├── vacuum_io_test.py           # 吸盘 Tool IO 单测
├── data/                       # 任务二标定/调参/验收数据（生成后提交留档）
│   ├── task2_offsets_v2.json       # 方块/托盘 XY 偏移 + 抓放 Z
│   ├── task2_verified_trays.json   # 人工验收托盘坐标
│   └── task2_tuning.json           # 调参工具产物（本地生成，已 gitignore）
└── resources/
    ├── visionmaster_task2_calibration.xml   # VisionMaster 九点标定结果
    └── pyaubo_sdk-0.24.1-*.whl             # AUBO SDK 安装包
```

> 所有运行时产物（拍照图、临时录音、任务二各区域原图/标注图/mask、`task2_*.json` 计划与错误日志、诊断目录）统一落进 gitignore 的 `output/`，便于赛后回溯排障。

### 模块职责

| 模块 | 对外接口 | 说明 |
|------|----------|------|
| `voice.py` | `wake()` / `listen()` / `speak()` / `is_exit()` | 本地 FunASR（SenseVoiceSmall）识别，pyttsx3 播报，内置 VAD 录音与近音词纠错 |
| `vision.py` | `capture()` | MVS 拍照，优先级：调试图 > 本地测试图 > 实机拍照 |
| `robot.py` | `move_to()` / `get_current_pose()` / `pick_and_place()` / `set_suction()` | AUBO 直线运动 + 到位轮询 + 末端 Tool IO 吸盘控制；连接失败自动降级「无臂模式」 |
| `llm.py` | `identify_image()` / `parse_task2_card()` | Qwen 视觉大模型；任务一返回播报文本，任务二返回六步 JSON |
| `task2_vision.py` | `ColorObjectDetector.detect()` / `CoordinateTransformer.pixel_to_robot()` | HSV 六色检测 + 矩形中心定位 + 九点标定像素→机器人坐标 |

## 3. 总体运行流程（main.py）

```
启动 → 初始化 Voice/Vision/Robot/LLM → 播报「请呼叫小具同学」
   ↓
循环：语音唤醒（唤醒词「小具同学」）
   ↓
播报「我已就绪，请下达指令」→ 等待任务提示词
   ↓
识别文本含「任务一」→ task1_run()    → 播报「任务已完成…」
识别文本含「任务二」→ task2_run()    → 播报「任务已完成…」
识别到「退出系统」→ 程序退出
```

要点：

- **两段式语音交互**：先喊「小具同学」唤醒，再喊「任务一 / 任务二」派发，唤醒词与任务词分开识别，任务流程内不再重复唤醒。
- **关键词匹配**：`main.py` 通过 `config.TASK1_COMMAND in command` / `config.TASK2_COMMAND in command` 判断派发。
- **热词纠错**：FunASR 打开 ITN 后「任务一」可能被转成「任务1」，已在 `config.ASR_CORRECTION_DICT` 中归一化。

## 4. 任务一流程（task/task1.py）

```
1. 机械臂移动到任务卡拍照位 config.ROBOT_TARGET（失败则兜底跳过，继续采集）
2. Vision.capture() 采集任务卡画面
3. LLM.identify_image() 调 Qwen 视觉识别场景内容，统一格式为「任务卡1中有A、B、C。」
4. Voice.speak() 语音播报结果
```

独立测试：`python task/task1.py`（绕过 main.py 的语音唤醒，直接跑流程）。

## 5. 任务二流程（task/task2.py）

任务二是核心，链路最长，分为「解析 → 识别 → 标定 → 抓放」四段。

### 5.1 解析任务卡

1. 机械臂移动到任务卡二拍照位 `TASK2_CARD_VIEW_POSE`；
2. MVS 拍照（任务卡原图上传分辨率更高，避免小字被过度缩放）；
3. `LLM.parse_task2_card()` 调 Qwen，按 `TASK2_CARD_PROMPT` 要求返回 JSON 数组：

```json
[
  {"step": 1, "block_color": "红色", "tray_color": "黄色"},
  ...
]
```

4. 程序强制校验：恰好 6 项、六色各出现一次（方块与托盘分别覆盖六色）、颜色名合法，否则报错。

### 5.2 识别方块与托盘

1. 移动到方块拍照位 → 拍照 → `ColorObjectDetector.detect(..., "方块")`；
2. 托盘坐标优先读人工验收文件 `task2_verified_trays.json`（`TASK2_USE_VERIFIED_TRAYS=True` 时），否则移动到托盘拍照位现场识别；
3. 颜色识别原理（OpenCV）：
   - **HSV 阈值分割**：方块与托盘**分区配置** HSV 范围（方块紫 H≈128~132 与托盘印刷紫 H≈171~176 不同，必须分开）；
   - **矩形检测**：`cv2.minAreaRect` 求最小外接矩形得到中心点；
   - **六色兜底**：HSV 直接检测异常时，改用「HSV 覆盖率 + HSV 色相距离 + Lab 颜色距离」加权联合评分，对六色做全局一对一分配，排除台外杂物；
4. `validate_six_colors()` 校验六色齐全。

### 5.3 像素 → 机器人坐标标定

坐标换算分两步：

1. **九点标定（VisionMaster）**：`CoordinateTransformer` 读取 `resources/visionmaster_task2_calibration.xml` 里的 `CalibMatrix`（3×3 单应矩阵），把像素坐标映射到标定平面世界坐标（mm）。标定文件由现场用 VisionMaster 生成，命名为 `visionmaster_task2_calibration.xml` 放入 `resources/`；标定原点用**基座坐标**（mm/rad）填进 config。**务必保证方块拍照点与托盘拍照点在基座坐标下的 Z 高度相同、rz（相机旋转轴）相同**，否则两块区域无法共用同一标定矩阵；
2. **偏移补偿（人工对准）**：`task2_offset_calibrate.py` 用示教器把吸盘移到某个参考色的真实中心，读取 AUBO 基座 TCP，与「预测值」做差，得到方块区/托盘区各自的 **XY 偏移** 和 **抓放 Z**，写入 `task2_offsets_v2.json`。

最终机器人坐标：

```
机器人位姿 = 标定原点位姿 + 世界坐标(mm) + XY偏移(mm) + 目标Z(mm) + 姿态
```

其中方块用 `TASK2_BLOCK_CALIBRATION_ORIGIN_POSE` / `TASK2_BLOCK_PICK_Z`，托盘用 `TASK2_TRAY_CALIBRATION_ORIGIN_POSE` / `TASK2_TRAY_PLACE_Z`。

> **抓取 Z 高度说明**：`TASK2_BLOCK_PICK_Z` 默认 28.00mm（略低于方块顶面约 30mm，吸盘端有弹簧，压一下贴合更紧更好吸）。抓取 Z **偏高会吸不住、偏低会撞**，推荐 28mm。但标定脚本 `task2_offset_calibrate.py` 会把自动读取的 TCP Z 写入偏移文件覆盖 config 默认值（当前偏移文件里块抓取 Z≈30.36、托盘放置 Z≈29.37）。若现场发现自动测的 Z 不合适，可把 `config.TASK2_MANUAL_Z_OVERRIDE = True`，改用手动填写的 `TASK2_BLOCK_PICK_Z` / `TASK2_TRAY_PLACE_Z`（XY 偏移仍自动读 JSON），无需再手改 JSON。

### 5.4 六步抓放

```
for 每一步 in 装配计划:
    Robot.pick_and_place(pick_pose, place_pose)
```

`pick_and_place` 的动作序列（`robot.py`）：

```
抓取点上方接近 → 下降到抓取点 → 真空泵开（关泄压阀）→ 抬升 → 水平移动到放置点上方
→ 下降到放置点 → 真空泵停 + 泄压阀开（释放）→ 抬升
```

### 5.5 吸盘 Tool IO 控制

吸盘是**末端 Tool IO**，不是控制柜 Standard DO（已实机验证）。`robot.set_suction()`：

| 动作 | 泄压阀 IO0 | 真空泵 IO1 |
|------|-----------|-----------|
| 吸取（开启） | 关闭 | 开启 |
| 释放（关闭） | 短暂开启泄压后关闭 | 关闭 |

配置项集中在 `config.py`：`TOOL_IO_VENT_INDEX=0`、`TOOL_IO_PUMP_INDEX=1`、`TOOL_IO_VOLTAGE=24`，写 IO 后做回读校验。

## 6. 现场调参清单（config.py）

现场一般只需改：

| 参数 | 含义 |
|------|------|
| `CAMERA_IP` | 海康相机 IP |
| `ROBOT_IP` / `ROBOT_PORT` / `ROBOT_USER` / `ROBOT_PASSWORD` | 遨博机器人连接 |
| `ROBOT_TARGET` | 任务卡一拍照位（六维位姿，需示教标定） |
| `TASK2_*_VIEW_POSE` / `TASK2_*_CALIBRATION_ORIGIN_POSE` | 任务二三区拍照位与标定原点（方块/托盘拍照点需保证基座 Z、rz 一致） |
| `TASK2_MANUAL_Z_OVERRIDE` | 手动定抓放 Z（`True` 时用 config 的 Z 覆盖偏移文件里的 Z，XY 仍自动读 JSON） |
| `TASK2_HSV_RANGES` / `TASK2_BLOCK_HSV_RANGES` / `TASK2_TRAY_HSV_RANGES` | 六色 HSV 阈值（建议用 `task2_tuner.py` 调好后写 `task2_tuning.json`） |
| `DASHSCOPE_API_KEY` | 大模型密钥（用环境变量或本地 `secrets.json`，勿提交 Git） |
| `ASR_MODEL_DIR` | FunASR/SenseVoiceSmall 本地模型目录 |

## 7. 目录定位与注意事项

- **`data/` 存放任务二标定数据**：`task2_offsets_v2.json`（偏移 + 抓放 Z）、`task2_verified_trays.json`（人工验收托盘坐标）已提交留档；`task2_tuning.json` 由 `task2_tuner.py` 生成、已 gitignore，换机器或光照变化后需重新调参生成。
- **`output/` 是统一运行时产物目录**（已 gitignore）：任务一拍照图、临时录音 `temp_voice_command.wav`、任务二各区域原图/标注图/mask、`task2_*.json` 计划与 `task2_error_*.log` 错误日志、LLM 原始返回 `task2_llm_*.txt`，以及 `diagnostics/`、`offset_calibration/`、`tray_verification/` 子目录，全部落在这里，便于赛后回溯排障。
- **路径锚定**：所有路径由 `config.py` 的 `PROJECT_ROOT`（`Path(__file__).resolve().parent`）推导，换机器、换启动目录都无需手改相对路径；仅 `CAMERA_IP` / `ROBOT_IP` / `MVS_SDK_DIR` 等外部硬件或软件安装参数需现场配置。
- 需要运行 `task2_offset_calibrate.py` 生成 `data/task2_offsets_v2.json` 后，任务二才允许真实抓放（`TASK2_REQUIRE_OFFSET_FILE=True` 时会强制检查该文件存在）。
