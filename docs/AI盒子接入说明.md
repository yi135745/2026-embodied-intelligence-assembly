## 交互逻辑及唤醒词差异

`Voice.wake()` → 就绪播报 → `Voice.listen()` → 原有任务派发，保持原来的两段式交互。任务一、任务二无需改动语音调用。

盒子原生关键词模型为“小E同学”，不是比赛用的“小具同学”。当前适配使用 `/v1/asr` 的 `wakeup_required=false, prewoken=true`，直接让盒子录音并识别文字；上位机纠错后检查是否包含 `config.WAKE_WORD`（默认“小具同学”）。等待唤醒期间也能识别“退出系统”。它是**ASR 文字唤醒**，不等同于原生关键词唤醒。

盒子分支不使用原来 0.65 相似度的宽松匹配，避免“小E同学”也被当作“小具同学”。仍沿用显式的近音词纠错表，例如“小菊同学”→“小具同学”。直接说“任务一”不会越过唤醒阶段。

请先单独说“小具同学”，听到就绪播报后再说“任务一”或“任务二”。不支持唤醒词和任务词连说成一句，也未增加播报中唤醒打断。文本唤醒依赖每轮完整 ASR，首次加载耗时、轮间空隙、噪声下误识别及延迟都需现场测。若赛方要求原生关键词检测，应向设备方取得匹配的关键词模型与配置说明；仅修改服务端唤醒提示文字不能视为更换了模型。当前方法是否满足具体验收口径仍需确认。

`speak()` 使用盒子离线 Piper，同步返回后才继续下一步。不依赖 Edge TTS 外网服务。

## 配置与故障行为

`config.py` 中默认 `VOICE_BACKEND="ai_box"`、`AI_BOX_URL="http://192.168.1.11:8765"`，均可用同名环境变量覆盖。`AI_BOX_*` 参数控制 HTTP 超时、开口等待、最长录音和 VAD 阈值。省赛 `THRESHOLD`、`SILENCE_LIMIT`、`RATE`、`ASR_MODEL_DIR` 和 `TTS_RATE` 不控制盒子服务。

只在成功的静音响应 `NO_SPEECH_DETECTED` 且未标为不可重试时返回空文本继续等待。断线、识别超时、设备错误、缺少结果字段以及 TTS 跳过/打断均抛出 `VoiceServiceError`，不会误报完成，不会自动切回电脑录音或重放请求。客户端超时/退出并不证明盒子上的请求已停止；先等本轮采集/播放结束，再排查或重试，不要并发开多个录音客户端。

省赛回归可以手动设置 `VOICE_BACKEND="local"`；此时才加载本地 FunASR、PyAudio、pyttsx3。盒子模式的语音模块和独立测试脚本仅依赖 Python 标准库，其他视觉/机器人模块仍使用原有环境。
