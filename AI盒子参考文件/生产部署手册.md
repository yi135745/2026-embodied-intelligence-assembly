# SpeechReleaseServer 生产部署手册

面向：**对外批量部署**、产线装机、现场运维。  
适用产物：Linux **aarch64** 闭源包 `SpeechReleaseServer/`。

---

## 1. 发布包内容

解压后典型结构：

```text
SpeechRelease-<arch>-<YYYYMMDD>/
  SpeechReleaseServer/          # 运行目录（可整体拷贝到目标机）
    SpeechReleaseServer         # 可执行文件
    speech_server.json          # 启动配置（现场可改）
    VERSION.txt
    README_RUN.txt
    MODELS/
      asr/                      # 离线 ASR
      tts/                      # 离线 Piper TTS
    _internal/                  # 运行时依赖（勿删）
  SpeechReleaseClient/          # HTTP 验收客户端（源码，标准库）
    准备验证环境.sh
    scripts/verify_*.py
    speech_release/client.py
  docs/
    生产部署手册.md             # 本文
    用户交互手册.md             # 给最终用户/演示员
    测试使用教程.md             # 发布包验收步骤
    HTTP接口协议.md             # 上位机 HTTP/WS 协议
  启动打包语音服务.sh           # 一键启动
  安装桌面快捷方式.sh
  VERSION.txt
```

**原则**：整目录拷贝，不要只拷贝单个二进制；`MODELS/` 与 `_internal/` 必须同目录。

## 2. 目标机要求

| 项 | 要求 |
| --- | --- |
| CPU/OS | Linux **aarch64**（如 Ubuntu 22.04 ARM） |
| 音频输入 | 可用默认麦克风（USB 阵列/板载均可） |
| 音频输出 | 扬声器或耳机；系统需有播放能力（`aplay`/`ffplay`/`mpv`/`play` 之一） |
| 系统库 | 建议安装 `libportaudio2`（录音） |
| 网络 | 默认 **离线可跑**（piper）。仅当 `tts.backend=edge_tts` 时需要外网 |
| 端口 | 默认 `8765`（可在配置中修改） |
| 权限 | 对运行目录可写（写 `speech_server.log`）；麦克风设备可读 |

安装音频库示例：

```bash
sudo apt update
sudo apt install -y libportaudio2 alsa-utils
# 可选播放器（任选其一）
sudo apt install -y sox ffmpeg
```

## 3. 单机安装

```bash
# 1) 解压到固定目录（示例）
sudo mkdir -p /opt/speech
sudo tar -xzf SpeechRelease-aarch64-YYYYMMDD.tar.gz -C /opt/speech
cd /opt/speech/SpeechRelease-aarch64-YYYYMMDD

# 2) 赋权
chmod +x SpeechReleaseServer/SpeechReleaseServer
chmod +x 启动打包语音服务.sh
chmod +x 安装桌面快捷方式.sh

# 3) 启动
./启动打包语音服务.sh
# 或安装桌面图标后双击「SpeechRelease语音服务」
./安装桌面快捷方式.sh
# 或
cd SpeechReleaseServer && ./SpeechReleaseServer
```

### 3.1 桌面启动入口（可选）

发布包根目录执行：

```bash
./安装桌面快捷方式.sh
```

会在 `~/Desktop/` 与 `~/.local/share/applications/` 生成 **SpeechRelease语音服务** 图标（指向 `启动打包语音服务.sh`）。首次双击若提示不受信任，勾选「允许执行」即可。

健康检查：

```bash
curl -s http://127.0.0.1:8765/health | python3 -m json.tool
```

期望：`ready=true`，`provider=real`，且 `models.asr_exists` / `piper_exists` / `keyword_exists` 为 `true`。

停止：在前台窗口 `Ctrl+C`；或：

```bash
fuser -k 8765/tcp
```

## 4. 批量部署（推荐流程）

### 4.1 标准镜像装机

1. 在模板机完成一次安装与 `/health` 验收。  
2. 将整个 `SpeechRelease-*/` 目录打入系统镜像或作为独立组件同步。  
3. 开机后由 systemd / 自启脚本拉起（见下节）。

### 4.2 rsync / scp 批量下发

```bash
# 从构建机推到多台目标机（示例）
for host in robot01 robot02 robot03; do
  rsync -avz --delete \
    SpeechRelease-aarch64-YYYYMMDD/ \
    "${host}:/opt/speech/SpeechRelease/"
  ssh "${host}" 'chmod +x /opt/speech/SpeechRelease/SpeechReleaseServer/SpeechReleaseServer'
done
```

### 4.3 现场仅改配置、不换包

批量机若只需改唤醒词提示、端口、TTS：

1. 只同步 `speech_server.json`  
2. 重启服务  

**不要**在现场手动删 `_internal/` 或半量覆盖二进制。

## 5. 开机自启（systemd 示例）

`/etc/systemd/system/speech-release.service`：

```ini
[Unit]
Description=SpeechReleaseServer ARM Speech Service
After=network.target sound.target

[Service]
Type=simple
WorkingDirectory=/opt/speech/SpeechRelease/SpeechReleaseServer
ExecStart=/opt/speech/SpeechRelease/SpeechReleaseServer/SpeechReleaseServer --host 0.0.0.0 --port 8765
Restart=on-failure
RestartSec=3
# 如需指定用户与音频组，取消注释并改成实际用户：
# User=bst
# Group=audio

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now speech-release.service
sudo systemctl status speech-release.service
```

## 6. 常用配置（`speech_server.json`）

文件位置：可执行文件同目录。改完必须**重启**。

| 场景 | 改法 |
| --- | --- |
| 改端口 | `"port": 8765` |
| 离线播报（默认） | `"tts": { "backend": "piper" }` |
| 在线播报 | `"tts": { "backend": "edge_tts", "voice": "zh-CN-XiaoxiaoNeural" }` |
| 改唤醒提示词 | `"wakeup": { "keyword": "小E同学" }`（须与 `.table` 模型一致） |
| 嘈杂环境 | `"vad": { "threshold": 0.6 }`（略提高） |
| 打断后开口更宽裕 | `"vad": { "start_timeout_s": 8.0 }` |
| 日志 | `"console": { "log_file": "speech_server.log", "show_logs": true }` |

完整字段说明见研发侧 `speech_release/README.md`。现场运维优先只改上表项。

## 7. 协议端点（供上位机集成）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 就绪与模型自检 |
| POST | `/v1/asr` | 唤醒（可选）+ 录音 + ASR |
| POST | `/v1/tts` | 合成并播放 |
| POST | `/v1/tts/cancel` | 取消当前播报 |
| WS | `/v1/events` | 事件流（如 `wakeup.detected`） |

默认 Base URL：`http://<设备IP>:8765`。

ASR 常用字段：

- `wakeup_required=true`：先等唤醒词再录音  
- `wakeup_required=false` / `prewoken=true`：已唤醒，直接录音（打断后二次采集）

**完整请求/响应字段、错误码、WS 事件与示例**见：[HTTP接口协议.md](./HTTP接口协议.md)。

## 8. 上线验收清单（每台机必做）

1. `./SpeechReleaseServer --help` 可执行  
2. `/health` → `ready=true`  
3. TTS：能听到一句播报  
4. 唤醒：说配置中的唤醒词，能触发  
5. 指令：唤醒后说短句，ASR 返回非空文本  
6. （可选）播报中再说唤醒词，TTS 被取消  

用户口令操作细节见《用户交互手册》。

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 端口占用 | `fuser -k 8765/tcp` 后重启 |
| `ready=false` / 模型不存在 | 检查同目录 `MODELS/asr`、`MODELS/tts` 是否完整 |
| 无声音 | 检查默认播放设备、音量、是否安装播放器 |
| 录不到音 | 检查麦克风权限、`libportaudio2`、系统默认输入设备 |
| 唤醒无反应 | 确认说的是配置关键词；环境噪声；距离麦近一些 |
| 打断后“没听到指令” | 打断后 **3 秒内** 立刻说指令；或把 `vad.start_timeout_s` 调到 `8` |
| edge_tts 失败 | 检查外网；或改回 `piper` 离线 |

日志：运行目录 `speech_server.log`。

## 10. 回滚

1. 停止服务  
2. 用上一版本完整目录覆盖当前目录（保留现场改过的 `speech_server.json` 如需）  
3. 启动并跑第 8 节验收  

禁止只回滚单个文件混用新旧 `_internal/`。

## 11. 版本与支持边界

- 本产物为**闭源可执行服务**，不含 Python 源码与研发验证脚本。  
- 职责：唤醒 / VAD / 录音 / ASR / TTS / HTTP·WS 协议。  
- 不负责：任务编排、机械臂控制、业务证据落盘。
